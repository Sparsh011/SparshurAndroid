# Bridge learning lab, version 1

The owner's later Mac mini networking lesson is specified separately in
[RELAY_V1.md](RELAY_V1.md). It implements WSS connection authentication only;
neither local message format below is silently reused as a relay envelope.

The next independent lesson is specified in [PAIRED_V2.md](PAIRED_V2.md).
The v1 messages below retain their original behavior.

This is an isolated, user-requested encryption / plaintext comparison exercise.
It is NOT Bridge's production E2EE protocol. It does not complete Phase 0 or 1.
Human review is required before reusing crypto or protocol code outside this lab.
These specs live in the Android checkout until the planned monorepo exists.

## Local encryption

AES-256-GCM, 128-bit authentication tag, 96-bit provider-generated random nonce.
The AES key is generated by AndroidKeyStore and never exported to the receiver.
The key allows only GCM with no padding, randomized encryption required, and no
per-operation biometric prompt (foreground learning exercise). Hardware backing
is inspected rather than assumed. Keystore operations run off the main thread.

Each encryption reserves a durable increasing counter BEFORE encryption. A
single process-wide lock protects creation/reservation. Limit: 10,000 attempts
per key. Random 96-bit nonce collision probability at that limit is approximately
6.3e-22; randomized nonces are probabilistic, not a mathematical uniqueness proof.
No caller supplies an encryption nonce. Decryption uses the recorded nonce.
Do not reset counters or silently replace a key. Uninstalling removes the key.

Metadata: version 1, canonical lowercase UUID sender_id and message_id,
recipient_id `laptop-observer`, message_type `text`, counter 1..10000.
UUIDv4 is used in the lab only; the future production spec calls for UUIDv7.
The exact associated data is UTF-8, with no final newline:

    bridge-lab|1|<sender_id>|laptop-observer|text|<counter>|<message_id>

All those fields are authenticated. The algorithm is fixed by version; there is
no algorithm negotiation. The nonce and AAD are public. GCM output contains
ciphertext followed by the 16-byte tag. Empty messages and messages >4096 UTF-8
bytes are rejected. Local ciphertexts are kept only in app memory.

## Observation transport (debug build only)

HTTP POST `/message` to a literal private IPv4 / loopback / Android emulator
address, port 8787 by default. No DNS, credentials, redirects, public addresses,
proxy, automatic retries, or TLS downgrade. Connect/read timeout 5 seconds.
The local lab deliberately uses HTTP so the plaintext difference is visible.
Production must use TLS and a separately designed E2EE protocol.

Encrypted JSON has EXACTLY these fields (Base64 is standard, padded, no wraps):

    lab_version, mode, algorithm, message_id, sender_id, recipient_id,
    message_type, counter, nonce, aad, ciphertext

`mode` is `encrypted`, `algorithm` is `AES-256-GCM`. The body NEVER includes the
plaintext, AES key, or key alias. `ciphertext` includes the authentication tag.
The receiver validates metadata, canonical Base64, sizes, nonce length, tag
minimum length and exact reconstructed AAD, but CANNOT authenticate/decrypt it.
Successful receipt means observed bytes only, never cryptographic verification.

Readable comparison JSON has EXACTLY `lab_version: 1`, `mode: plaintext`,
`message_id` (new UUIDv4), and `text`. It requires its own explicit UI action.
Only use invented sample messages. This deliberately sends readable content.

Responses: 202 new observation; 200 duplicate observation; JSON
`{"accepted":true,"duplicate":false}` (or true for duplicates). Bad schema 400,
wrong content type 415, oversize body 413, wrong route 404, reused ID with a
different body 409, expired observation session / capacity 409. The client
checks the receipt format. A receipt is unauthenticated in this HTTP lab.

Receiver state is bounded to 1000 message digests and 40 display events, in RAM
only. Restart starts a new session. It rejects new IDs when full rather than
forgetting dedup entries. No durable delivery/replay guarantee is claimed.
The observer page and event feed are loopback-only; POST is LAN-accessible.
The receiver checks private source addresses, JSON size, read timeout, browser
Origin, and never prints bodies to terminal logs. No external web assets.

## Test vectors

`test-vectors.json` contains a NIST AES-256-GCM known-answer vector and a
lab-shaped fixed-key / fixed-nonce vector with exact AAD and JSON. These fixed
values are TEST ONLY; production code never accepts supplied encryption IVs.
